Ingress outage: chaos experiment for Kubernetes

A bad config reload takes down a share of the ingress controller pods and keeps them down. The application behind them is perfectly healthy; nobody can reach it.

What it tests
ingress controller replicas, anti-affinity, edge availability
The hypothesis holds when
Several ingress replicas on different nodes: the survivors keep serving while the failed ones are fixed.
It breaks when
One ingress replica is a single point of failure for everything behind it.
