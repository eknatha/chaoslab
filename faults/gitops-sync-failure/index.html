Bad commit synced: chaos experiment for Kubernetes

A commit with a bad memory limit (16MiB instead of 16Gi) is synced and the pods are restarted. Self-heal faithfully re-applies the bad commit, because Git is the source of truth. Only an automated rollback undoes it.

What it tests
rollback to last good revision, difference between self-heal and rollback
The hypothesis holds when
Automated rollback to the last good revision restores the workload within the interval.
It breaks when
Self-heal alone keeps enforcing the broken configuration, and the pods OOM in a loop.
