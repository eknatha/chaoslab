ConfigMap deleted: chaos experiment for Kubernetes

A ConfigMap the pods start from is deleted and some pods are restarted. Running pods keep their loaded configuration, but every replacement fails with CreateContainerConfigError.

What it tests
startup dependence on configuration, safe rollout of config changes
The hypothesis holds when
Enough running pods to carry traffic until the ConfigMap is restored.
It breaks when
Each restart permanently removes a working pod, because nothing new can start.
