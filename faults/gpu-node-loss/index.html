GPU node loss: chaos experiment for Kubernetes

The busiest GPU node stops reporting. Its inference pods leave the Service at once, and each replacement has to schedule onto a GPU and load model weights before it can serve.

What it tests
GPU spare capacity, slow model load, eviction timing
The hypothesis holds when
Spare replicas carry the load while replacements load their weights, and quick eviction starts them early.
It breaks when
The default five minute toleration delays replacement, and a cold model takes tens of seconds to load.
