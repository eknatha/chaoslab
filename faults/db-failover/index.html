Primary database failover: chaos experiment for Kubernetes

The primary database goes away and a standby is promoted. Every write fails until it does. How long that takes depends on how the database is deployed.

What it tests
multi-AZ failover time, retries, read-only degradation
The hypothesis holds when
Automatic failover completes in seconds, and retries plus a read-only mode cover what is left.
It breaks when
A single instance or a manual failover means minutes of errors.

Reference

  • PostgreSQL high availability
  • Amazon RDS Multi-AZ
